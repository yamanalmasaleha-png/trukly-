# BiteShark Engineering Glossary

Exact definitions grounded in the BiteShark codebase. Avoid mixing customer-facing labels with legacy table or variable identifiers without consulting this table.

| Term | Code / DB / UI Identifiers | Meaning in BiteShark |
|---|---|---|
| **Vendor / Listing / Spot** | Table `vendors` (`id TEXT`), UI "Spot" / "Food truck" / "Listing", legacy API `/api/trucks*`, legacy FK `truck_id` | Any of the 59+ Sonoma County food trucks, pop-ups, cafés, farm stands, or farmers markets in the canonical PostgreSQL catalog (`migrations/014_unified_discovery_catalog.sql`). Early migrations (`001`–`010`) used `truck_id`; governance migrations (`011`+) use `vendor_id` referencing `vendors(id)`. |
| **Primary vs Neighborhood Listing** | `vendors.listing_kind` (`'food_truck'` vs `'farmers_market'`, `'farm_stand'`, `'coffee_shop'`, `'popup'`), `item.extra` boolean in `lib/discovery.js` | Both render through `cardHTML(t)` in `public/app.js`, while `item.extra === true` routes detail views through `extraDetail(t)`. |
| **Ownership Status** | `vendors.ownership_status` (`'unclaimed'` \| `'pending_review'` \| `'claimed_verified'` \| `'suspended'`) | Tracks whether a real business operator has been approved via `vendor_applications` (`migrations/018`). Unclaimed listings never accept live vendor mutations. |
| **Vendor Membership** | Table `vendor_memberships (vendor_id, user_id, role)` (`'owner'` \| `'staff'`) | Links an `auth_users.id` to a `vendors.id`. `Vendor Owner` has full vendor management & staff-invite rights; `Vendor Staff` can update live location, schedule, and pickup pagers (`lib/authz.js`). |
| **Admin: Top** | `platform_roles.role = 'top'` (legacy `'admin'`), `ctx.isTopAdmin` | Highest platform governance tier (`server/admin-routes.js`). Exclusive authority over account roles/suspensions, vendor approvals, permanent restrictions, feature controls, compliance readiness approvals, email readiness, and Act-on-Behalf mutations. |
| **Admin: Mod** | `platform_roles.role = 'mod'` (legacy `'moderator'`), `ctx.isModerator` | Operational moderation tier. Can review community queues/reports, triage support tickets, add readiness/application notes, apply temporary vendor restrictions (`<= 72h`), and view `mod_visible = true` diagnostics. |
| **Act-on-Behalf (AoB)** | Headers `X-BiteShark-Act-On-Behalf` + `X-BiteShark-Support-Reason` | Explicit audited mode allowing `Admin: Top` ONLY to execute vendor operations on behalf of a vendor with an `8..240` char support reason recorded in `audit_logs`. |
| **Viewpoint Preview** | `sessionStorage['biteshark_admin_viewpoint_v1']`, Header `X-BiteShark-Viewpoint: preview` | Read-only admin inspection mode (`?viewpoint=customer` or `?viewpoint=vendor&vendor_id=...`). Server Step 0 (`server/app.js`) rejects all mutations except logout with `403 ADMIN_PREVIEW_READ_ONLY`. |
| **14+ Age Eligibility Gate** | `lib/age-policy.js`, `auth_users.age_eligibility_status`, cookie `__Host-bs_age_gate` | Proposed product policy (`2026-11-draft-14plus-v1`, pending legal review) requiring users to be >= 14 years old in `America/Los_Angeles` without storing raw DOBs. |
| **Event Inquiry (Booking)** | Table `bookings`, `POST /api/bookings/create`, flag `event_inquiries` | **Inquiry-only** catering/event request (`pending` -> `accepted` / `declined` / `cancelled`). BiteShark processes zero payments or binding contracts. |
| **Pickup Pager** | Table `pickup_pagers`, `/api/pager/*`, `#pagerScreen` | Order-ready status tracker (`cooking` -> `almost` -> `ready` -> `collected` / `cancelled`) accessed by customers via capability UUID (`#pager=<uuid>`) with optional RFC 8291 Web Push notifications. |
| **Feature Control** | Table `feature_controls`, `FEATURE_CONTROLS_REGISTRY` (`lib/feature-controls.js`) | Live PostgreSQL-backed `Admin: Top` switch (`enabled` \| `paused` \| `hidden`, audience `all` \| `staff_beta`), subordinate to environment emergency stops (`BITESHARK_PAUSE_WRITES`, `PUSH_PROVIDER_MODE`). |
| **Diagnostic Incident Group** | Tables `diagnostic_incident_groups` & `diagnostic_event_samples` (`lib/diagnostics.js`) | Deduplicated operational error bucket keyed by `SHA-256(component \| feature_key \| route_template \| error_code)` with PII-redacted bounded samples and optional `support_issue_diagnostic_links`. |
| **Runtime Adapter** | `@biteshark/runtime-adapter` (`packages/runtime-adapter/index.js`) | First-party `AsyncLocalStorage` + `WeakMap` bridge binding `db` (`pg.Pool`) and server-verified `req.user` across handlers (replaced retired Hatchable SDK in `docs/VPS_ONLY_TRANSITION.md`). |
